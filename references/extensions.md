# 扩展与纠错规则

标准生成器覆盖常见通知及表格，不默默降级复杂场景。

1. 先用原PDF和format-standard.md明确新增要素及适用条款；保留原输入和数据。
2. 优先复用office.py中的RULES、paragraph、write_font、border、docx_table和单位换算，不重新猜参数。新要素必须同时补生成分支、输入校验、结构审查和反例测试。
3. 封面：必须使用用户提供的真实校徽、会徽，校徽在左；标题、落款按规范允许的字号。目录须在最终分页后更新，逐项核对标题与页号。未实现这些要素时不能用普通通知替代策划案。当前标准生成器遇到cover/toc会明确阻断。
4. 横排：不能只把orientation改为landscape。根据实际装订方向验证单、双页表头朝向及公文页码位置；在PDF中分别检查奇偶页。当前生成器仅支持竖向，避免伪造横排合规。
5. 保密附件：原文与示例的首行位置存在组合问题。未明确处理依据时，不压掉任何标识，不擅自重定义原文；当前组合会阻断。
6. Word合并组织信息：先核实和排序记录，再仅合并同组连续同值组织单元格；保留行数及原始逐行信息，复查续页和边框。不能合并姓名、学号或公式。标准代码不自动合并Word单元格，必要时补充实现并目检。
7. 既有复杂文件：先解析保存真实内容、表格、公式、图片和原结构，再映射输入契约。不能仅提取纯文本后声称完整保留。不能表达的数据/样式/批注/签章等必须明确报告，不得悄悄丢弃。
8. 字体缺失：本地提供的目标字体由程序私有加载。新增真实目标字体时运行add_fonts.py更新字体清单，再重跑doctor；系统已有字体也可通过fontconfig发现，不得给替代字体改名。个别生僻字仅按原文允许的单字替代规则处理，须新增逐字例外及PDF字形复核后才能扩展放行。
9. 引擎错误或分页缺陷：先查看具体异常/预览，最小修改源JSON或代码，再运行测试、生成、机检、同源PDF导出和全部页审查。不得只修PDF后留下不对应的Word/Excel。

示例（扩展时复用固定代码，而非另写近似样式）：

```python
from office import paragraph, write_font
from docx.shared import Pt

# 已读取真实素材、确认封面要素后，可复用标题规则，再登记规范允许的字号调整。
p = paragraph(doc, actual_title, 'Title')
for run in p.runs:
    write_font(run, '方正小标宋简体', 24)
# 必须同步扩展auditor；原Title检查器仍要求二号，不能通过改manifest绕过。
```
